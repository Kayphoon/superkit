# 写入与草稿维护

本协议用于正式知识的新建、正文编辑、改名、合并与 staging 整理。一次连贯批次检查全部实际输出；仅改正文也要核实变更事实、引用与附件。

## 落盘准备

本项目已有 `{{WIKI_DIR}}/superwiki-auto/` 即已接入，不另设初始化阶段。有内容需要落盘时自主补齐 `wiki-*` 目录；项目边界不明确时如实报告给用户，只在 `{{WIKI_DIR}}` 下写知识，不生成空模块或空草稿。

确认正式模块和写入目标在本项目内；{{LINK_RULE}}遇到同名内容或并发修改先核实，不自动替换。落盘前重新读取被别人改过的文件，不能用旧副本覆盖。

写入 staging 前用 `git check-ignore -q .wiki/staging.md` 确认草稿被 Git 忽略且未被跟踪。{{IGNORE_RULE}}保留其它规则，不忽略正式知识目录；草稿已被跟踪时停止新增内容，报告「仅从 index 移除、保留本地文件」的隔离方案，不擅自操作 index。项目不是 Git 仓库时跳过这一步。

## 写入与整合

正式知识只描述当前实现中已核实、与任务相关且有长期复用价值的事实。先比较相关模块的名称、description 和范围，再完整读取候选正文、必要附件与代码；共享关键词或 description 相似不足以认定重复。

优先增量更新已有功能模块或章节，没有合适入口才按主题新建。分支内已实现的功能可以与代码一起演进；未实现计划和未经核实的结论留 staging。独立知识纠错可以没有业务代码 diff，但须说明既有实现依据。

合并只去真正重复或已证实失效的现行说明，保留所有仍成立的独有子主题、触发词、边界、警告、示例及附件；历史决策不能改写成现行行为。不要为减少模块数合并无关主题，大范围重组与普通功能修改分开处理。

改名或合并时，先形成完整产物并迁移附件、完成校验，再更新其它 wiki、文档和代码注释中的相关路径及 `[[wiki-...]]` 引用。搜索残留引用，确认源目录无独有内容后才移除；未完成或价值不明时保留源内容。不另建迁移记录、旧路径对照或维护日志。

## 元数据与输出校验

新增、改名或修改 frontmatter 时，使用环境已有的标准 YAML 解析器实际解析，不用正则或自制解析器代替。仅改正文且 frontmatter 未变时不要求重复解析；发现既有元数据无效仍须修正或明确报告，不能以此跳过已知问题。

`name` 是 1..64 字符的字符串，匹配 `^[a-z0-9]+(-[a-z0-9]+)*$`，以 `wiki-` 开头、等于最终目录名且无重名。按主题命名（`wiki-<模块>`、`wiki-decision-<简述>`、`wiki-rule-<规则>`），不按任务或日期机械增殖。历史 `wiki_<topic>` 可读，实际维护时按本协议规范，不批量改无关模块。

`description` 是非空白字符串，原始解码值长度 1..1024；用正确缩进的 YAML 块标量（`description: |`）写主题、使用场景和必要边界，触发信息前置。路径、函数、状态码和操作细节放正文，不堆关键词或扩大范围。

最小模块示例；正文按实际主题组织，不要求固定章节：

```markdown
---
name: wiki-topic
description: |
  本模块的主题、使用场景和必要边界。
---

# 主题

> 约束：代码是唯一真相来源。使用本文内容前需核对当前实现，冲突时以代码为准。

记录已核实的行为、仓库相对路径、代码文件/符号依据和必要示例。
```

新建或本次触及的模块，均在 H1 下、其它章节前保留上述约束块原文；原生运行时可能直接读取知识而不先加载 superwiki-auto。

核对本批次全部输出的内容一致性、名称与目录、变更路径、Markdown 相对链接、`[[wiki-...]]` 和附件在实际审核版本中存在，无冲突标记、软链接或混入正式目录的草稿。名称、description 或路径改变后确认发现入口与引用仍有效。

不将凭据、私有会话、个人绝对路径或本机临时产物作为共享知识的依赖。草稿不随 Git 分享；跨成员交接通过已获授权的 Issue/PR，不擅自发布外部消息。

校验失败先修正；缺少解析能力或无法验证时说明具体缺口，不宣称通过、不删除源内容，不为此安装依赖、部署服务或新造检查器。格式正确不代表语义准确，完成后按 [审核协议](review.md) 自审。

## 草稿整理与清理

有后续核实、行动或复用价值的待核假设、问题、计划和范围外发现才进入 `.wiki/staging.md`。记录领域、证据/路径、适用分支和待核问题或下一步；沿用已有格式，不记录普通执行日志、一次性操作或进度。

遇到相关主题、新证据或完成相关提交时主动复查，只处理本次相关条目，不全量清空。每条重新核对当前实现，不直接复制草稿进 wiki，也不为清空草稿制造正式知识。

值得长期复用的内容核实、查重后合入正式模块。对应草稿在输出通过校验、且{{PERSIST_RULE}}后清理；已被正式知识覆盖的重复条目按同一条件清理。条件未满足、审核失败或仍有疑虑时保留，可标记整理位置。条件满足后自主核对并清理，不另等提醒；清理草稿本身从不需要暂存或提交。

已解决但无需沉淀、被证伪或已失效且没有剩余行动价值的条目，可以核实后直接清理，不要求写入 wiki 或等待无关提交；在本次回复简述原因，不另建清理日志。

仍待确认、等待条件或有行动价值的条目保留，不按存放时间删除。涉及别人的未完成任务、并发编辑或价值不明时保留并报告；用户明确只读时不执行任何清理。
